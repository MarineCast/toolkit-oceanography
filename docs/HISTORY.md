# Ocean Conditions history

`python -m oceanography.history` extends the simple SST/chlorophyll products while preserving the accepted pilot until complete validation and explicit promotion. Public columns, units, H3 resolutions and pixel-centre aggregation are the same as [the daily workflow](DAILY.md).

The historical source plan reads the **actual native time coordinates**, not just archive start/end attributes. For each calendar date it selects MUR `analysed_sst`, and preferentially MODIS Aqua R2022 SQ `chlor_a`; it uses MODIS R2022 NRT `chlorophyll` only when SQ has no date and NRT has one. Source variable names differ deliberately. Both MODIS variables report mg m⁻³, but NRT is provisional and the combined record must not be described as homogeneous final-quality observations. NRT fills some earlier SQ date gaps as well as recent dates. The frozen external `plan.json` records every date's source. Where no source time exists, every approved cell is present with a null metric and the plan records null source selection. HTTP failures, failed checksums or wrong returned time axes stop processing; they never become missing-source days.

A frozen plan binds the approved study, exact membership/mask checksums, code and source metadata/time-axis receipts. Changing code or study after checkpoints exist requires a deliberately new run plan; the workflow refuses incompatible resume. Each source-specific calendar-month response is a regional subset, never global. Exact response bytes are retained losslessly compressed with response and compressed checksums. Source receipts include URL, time, size and elapsed time. Two requests may run concurrently; NetCDF processing is sequential, one day at a time, with precomputed native-pixel-to-H3 assignments. Monthly Parquet checkpoints have plan and source bindings. Native expanded scratch files are created by the current invocation and removed after use; existing sources/checkpoints/delivery are not deleted.

Budgets: 15 GB compressed response cache, 150 MB per expanded response, and a 10 GB free-disk floor. The 250 MB daily-pilot cap does not apply to this explicitly authorized history workflow. The measured 2009 seven-day MUR subset was 29.03 MB expanded, 3.54 MB wire transfer and 3.94 MB locally compressed; full history was estimated at 4–8 GB retained compressed sources. Processing and final readback are bounded by monthly/day batches. The final writer validates sorted date/cell identity and every approved member, streams final readback, and checks overlapping accepted output rows exactly before promotion. It retains previous delivery outside Data under the existing publication journal.

Example from the MarineCast workspace:

```sh
python -m oceanography.history --study config/study.v1.json --output Data/Oceanography --root Toolkits/toolkit-oceanography/.oceanography/history-20261026 --start 2009-01-01 --end 2026-10-26 --preflight
python -m oceanography.history --study config/study.v1.json --output Data/Oceanography --root Toolkits/toolkit-oceanography/.oceanography/history-20261026 --start 2009-01-01 --end 2026-10-26
```

The second command acquires and validates resumable checkpoints, **without replacing public output**. `--limit-jobs 2` bounds an initial execution check. Once the consumer is ready, repeat with `--offline --publish` to validate and promote complete history without network access. An outside-checkout wheel replay into a task-owned temporary output can validate the same final Parquet bytes before production promotion. For a new source vintage, choose a new explicit plan root; this prevents silent replacement of frozen metadata or source history.

Validation commands: `python -m pytest -q tests/test_daily.py tests/test_history.py`, then the full toolkit suite. Installed-wheel tests run from an outside-checkout test copy. Replay verifies raw receipt/checkpoint integrity, publication recovery, SQ precedence, native timestamp failures and exact pilot aggregation. Source receipt/catalog qualification remains outside the three public columns.

## Executed full-history result — 2026-10-26

The approved study was published for 2009-01-01 through 2026-10-25 with 6,507 dates and exact reporting membership: 2,427 R6 cells for SST and 463 R5 cells for chlorophyll. SST has 15,792,489 rows (14,935,480 nonnull; 857,009 null), range 4.0100–24.2737 °C. Chlorophyll has 3,012,741 rows (463,278 nonnull; 2,549,463 null), range 0.077265–86.3760 mg m⁻³. Counts and provenance remain outside the public metric tables.

All 429 monthly/source batches and raw/checkpoint checksum pairs passed. Sixteen independent daily-adapter comparisons across winter/summer dates and source variants matched exactly; all 7,281 SST and 1,389 chlorophyll accepted pilot rows were preserved exactly. The checkout suite passed 32 tests and outside-checkout installed-wheel tests passed 15. Installed-wheel candidate and promoted Parquet bytes matched. The full writer/readback streamed every date/member combination. Final files contain 214 monthly date-clustered row groups each; representative daily filters selected one group and read in approximately 2 ms after the first read (20 ms). Application acceptance remains owned by the app task.

One MUR June 2021 request exhausted bounded HTTP 503 retries; a cooldown retry succeeded and retained checkpoints were reused. No failed response was converted to a missing day. Measured acquisition process time, including preflight batches and retry, was 42.6 minutes. Source data occupy 4.173 GB compressed; public Parquets occupy 151.6 MB. Acquisition peaked at 225 MB resident memory; complete final assembly/readback peaked at 412 MB, within the stated budget. Native expanded monthly scratch is removed after processing, while receipts, compressed sources, checkpoints and the previous accepted pilot remain retained.

October 25 chlorophyll has no nonnull study cells despite a native source timestamp. The latest October date with local retrievals is October 17 (two cells). This is source missingness, not an app load error or permission to relabel older observations as current. SST retains values on the latest date. No full-history provider-issued availability record was established; these remain retrospective products, with provisional NRT explicitly identified.
